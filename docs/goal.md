# docs/goal.md —— 改造目标

> 初始化第 2 项「改造目标」的固化结果。方向由用户确认：**修 Bug + 加功能**。
> 单个需求的具体范围在每步 Spec 中细化；本文件只定方向、优先级、验收与回滚。

## 一、目标

1. **修 Bug**：按 `contracts/README.md` 登记的缺陷分级处理，先修"调用即失败"和高频路径。
2. **加功能**：在冻结契约之上**新增**能力，不改已有 API ID、键名与签名。

## 二、修 Bug 优先级

| 优先级 | 缺陷 | 处理策略 |
| :-- | :-- | :-- |
| P0 | C1：b2 `robot_state` 导入不存在的模块 | 仅改导入路径，不改签名 |
| P1 | C2：`PlayStop()` 恒返回 0；C3：g1 TTS 索引自乘 | 改为透传底层返回码 / 索引递增 |
| P2 | C5：`RecurrentThread` 零周期分支；C6：`ChannelPublisher.Write` 异常兜底 | 仅修异常路径，主链路行为不变 |
| P3 | C4 / C7 / C8：注册但未暴露的方法 | **只登记，不处理**，待有明确需求再评估 |

## 三、加功能边界

- 允许：新增 API ID（不与现有取值冲突）、新增可选关键字参数（带默认值）、新增机型目录、新增便捷方法（内部复用既有 API ID）。
- 禁止：修改现有服务名、API 版本、API ID 数值、请求 JSON 键名、返回元组形状。
- 具体功能项：**待定**。每项须先出 Spec，写明影响机型与契约影响面，经确认后实现。

## 四、验收标准

1. `contracts/` 中冻结的签名、服务名、API ID、JSON 键名、topic、CRC 字节数均未变化。
2. 改动涉及的模块有对应单元测试，且 `python -m unittest discover -s unitree_sdk2py/test/unit -t unitree_sdk2py/test/unit -v` 全绿。
3. `python -c "import unitree_sdk2py"` 与 `python unitree_sdk2py/test/crc/test_crc.py` 正常。
4. 受影响机型的示例脚本在无机器人时不因导入/构造报错（有机器人时另行联调确认）。
5. 单步改动不超过 3 个文件。

## 五、回滚要求

- 每步一个独立提交，提交信息注明对应缺陷编号或功能项。
- 任一步失败可直接 `git revert` 该步提交，不牵连前后步。
- 不删除、不重命名现有公开方法；确需废弃时保留旧名并转发。
